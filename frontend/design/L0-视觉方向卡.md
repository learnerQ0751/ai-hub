## 1. 判断先行

LiteLLM 的 UI 是**“够用级”管理台**：信息架构可信、操作流完整、组件覆盖齐，但视觉是默认后台的拼装感，品牌表达弱。

主人的目标是**公网作品集**，视觉完成度必须高于原站。因此定位是：

> **借它的信息架构与操作流；视觉语言重新做一版；不做换皮克隆，也不无参考自由发挥。**

本卡要确认的不是“像不像 LiteLLM”，而是“**保留什么、换掉什么、提升到什么水准**”。

## 2. 从截图读到的视觉语言

### 2.1 布局骨架

```text
┌──────────────┬─────────────────────────────────────────────┐
│ Logo/版本    │ 面包屑                         Docs Blog ⚙ │ 48px
├──────────────┼─────────────────────────────────────────────┤
│ AI GATEWAY   │ 页面标题                                     │
│  虚拟 Key     │ 一句话说明              [主操作]             │
│  Playground  │ ┌ tabs ──────────────────────────────────┐ │
│  模型与端点   │ │ 筛选栏：搜索 / 范围 / 列 / 过滤          │ │
│  MCP Servers │ ├────────────────────────────────────────┤ │
│  技能        │ │ 表格 / 卡片列表                          │ │
│  护轨        │ │ 行状态、行操作、分页                      │ │
│  策略        │ └────────────────────────────────────────┘ │
│  工具        │                                             │
│ OBSERVABILITY│                                             │
│  用量        │                                             │
│  排行榜      │                                             │
│  日志        │                                             │
│ ...          │                                             │
│ 账号         │                                             │
└──────────────┴─────────────────────────────────────────────┘
   侧栏 ~240px                 内容区（白底、24px 内边距）
```

- 固定左侧栏，按域分组；分组标题是 10px 全大写小字。
- 侧栏背景接近白色，当前项用浅灰底；没有强分隔线。
- 页面头部统一：标题 + 一行说明 + 右上主操作。
- 列表页统一骨架：tabs → 筛选栏 → 表格/卡片 → 分页。
- 详情多用抽屉/弹窗，少用独立详情页。
- 桌面优先，没有移动端适配证据。

### 2.2 取到的 token（截图取样）

| token | 值 | 置信度 | 来源 |
|---|---|---|---|
| 页面背景 | `#f3f4f6` | 高 | 登录页角落 |
| 表面/内容区 | `#ffffff` | 高 | 内容区直方图 |
| 侧栏背景 | `#ffffff` | 高 | 侧栏直方图 |
| 侧栏当前项 | `#f3f4f6` | 高 | 当前导航项 |
| 主文字 | `#111827` | 中高 | 深色文字取样 |
| 次文字 | `#60646c` | 中 | 弱化文字/标签栏 |
| 边框 | `#e6e7eb` | 中 | 头部发丝线 |
| 表头底 | `#fbfbfc` | 中 | 表头区域 |
| 主按钮 | `#111827` | 高 | 黑底白字 CTA |
| 品牌蓝 | `#0314be` | 中 | Logo 像素，受抗锯齿影响 |
| 图表强调色 | `#00b8d8` | 高 | 用量页柱状图 |
| 成功/失败色 | 存在绿/红徽标 | 低 | 未取到稳定底色 |

**读法**：LiteLLM 实际是“近黑 CTA + 深饱和品牌蓝 + 青色图表 + 白底灰边”的组合。品牌蓝与近黑 CTA 各自为政，是它看起来“拼装”的原因之一。新方案不要直接继承这组关系。

### 2.3 字体与密度

- 基础字号约 13px，页面标题约 24px；导航 13px，分组标签 10px 全大写。
- 字体像 Inter 一类无衬线；未核实。
- 表格 12–13px，日志行高约 30px；整体是高密度后台。
- 数字与 ID 用等宽字体；但正文层级偏平，页面“标题—说明—表格”之间的节奏靠留白而非字阶。

### 2.4 组件与模式（值得借）

- 一页一个主 CTA；行级状态 + 行级操作。
- 一次性密钥用阻断式弹窗展示，带复制与“只显示一次”警告。
- 数据页顶部有 Global / Team / User 范围选择器。
- 关联视图用 tabs 分组，不把导航撑爆。
- 日志支持 Live Tail 与自动刷新。
- 降级/价格缺口用横幅提示，而不是只藏在数据里。

### 2.5 观察到的弱点（必须换掉）

- Beta 徽标泛滥，导航和标题都在喊“实验性”，削弱可信度。
- 13px 一统，信息层级不够；扫读时缺少落点。
- 次文字对比度偏低；部分标签几乎看不清。
- 深饱和品牌蓝与近黑 CTA 冲突；按钮形状/权重在不同页面不统一。
- 桌面专用；窄屏没有可用方案。
- 表格密度高但没有分组、冻结列或强视觉锚点，长表容易串行。
- 空态与引导弱，首次使用靠猜。

## 3. 保留 / 换掉 / 提升

### 3.1 保留（信息架构与操作流）

1. **左侧按域分组的导航**：访问控制 / 能力目录 / 可观测 / 调试 / 系统。
2. **列表页统一骨架**：标题 + 说明 + 主 CTA → tabs → 筛选栏 → 表格/卡片 → 分页。
3. **抽屉/弹窗承载详情与创建**，避免为每个对象开独立详情页。
4. **行级状态与行级操作**；状态用文字 + 颜色，不只用颜色。
5. **一次性密钥弹窗**：阻断、复制、明确“只显示一次”。
6. **范围选择器**（租户/项目）置于数据页顶部，全局一致。
7. **日志 Live Tail / 自动刷新**；用量 KPI + 趋势。
8. **能力域的完整入口**：Key、模型、MCP、Prompt、RAG、日志、用量、审计、Playground。

### 3.2 换掉（视觉与体验债）

1. **不复制 LiteLLM 品牌蓝与黑色 CTA 的组合**；建立自己的单强调色体系。
2. **不用 Ant Design 默认蓝/默认圆角/默认阴影**；用 token 统一压掉“开箱味”。
3. **重建字号阶梯**：页面标题 / 区块标题 / 表体 / 辅助文字至少四级，不靠 13px 一统。
4. **降低徽标噪音**：只保留“状态”和“来源”两类徽标；实验性功能用文案，不用满屏 Beta。
5. **统一按钮形态与权重**：主操作、次操作、危险操作三类，全站一致。
6. **补齐三态**：每个列表的 loading 骨架、空态引导、错误可重试。
7. **补齐窄屏策略**：至少 768 可用；375 允许降级为“查看 + 关键操作”，不假装完整后台。
8. **表格可扫读**：冻结首列、行分组、数字右对齐、等宽数字、长文本截断 + 展开。

### 3.3 提升到什么水准

作品集验收线，不是“比 LiteLLM 好一点”：

- **5 秒可读**：登录后第一屏能回答“系统是否正常、钱花在哪、哪里出错”。
- **一致**：颜色、间距、圆角、阴影、按钮、表格、表单全部来自一套 token。
- **有结论的图表**：标题是问题，标注是答案；不做无标注的装饰图。
- **可访问**：正文对比度 ≥ 4.5:1，键盘焦点可见，状态不只靠颜色。
- **可信**：没有多余装饰、没有渐变玻璃、没有 3D；数据优先。
- **性能**：1440 桌面首屏（4G 模拟）2 秒内可交互；图表按需加载。

### 4.1 D1 已定要素

| 维度 | 结论 |
|---|---|
| 关键词 | 克制、精确、可信、可扫描、技术感 |
| 布局 | 左侧竖排导航；内容区自上而下：面包屑 → 标题 + 一行说明 → 筛选 → 表格/卡片 |
| 密度 | 高信息密度；表格行高约 **36px** 量级；靠行高与间距实现，不靠压字号 |
| 分割 | **1px 细灰分割线**；不使用大色块分区 |
| 圆角 | **3px** |
| 阴影 | **无阴影** |
| 状态 | **小色点 + 文字**（健康/异常/未知），不用药丸状态、不用大色块 |
| 数字与 ID | ID、Key、端点、参数、数字用**等宽字体**，表格数字右对齐、tabular-nums |
| 强调色 | 克制使用：主色只出现在**主按钮与链接**；其余用墨色与灰阶 |
| 字号阶梯 | **不沿用 LiteLLM 的 13px 一统**；已定义 12 / 13 / 14 / 16 / 20 / 24 / 30 七级，正文 14px、表格 13px、页面标题 24px |
| 明暗 | 亮色为默认；暗色不在首版范围 |

## 5. 补位参考（决策记录，未采用）

LiteLLM 提供的是“骨架”，不足以提供作品集需要的视觉完成度；这个判断仍然成立。但主人本轮只选定 D1，**未指定补位参考**，以下候选仅作为决策记录保留，L2 不擅自引入：

| 候选 | 可借什么 | 风险 / 代价 |
|---|---|---|
| **Linear** | 字体层级、克制的边框与阴影、紧凑但安静的产品感 | 偏产品协作工具，不是数据后台 |
| **Stripe Dashboard** | 表格与筛选用法、空态与引导、金融级可信感 | 完成度高，容易“像 Stripe” |
| **Vercel Dashboard** | 单色外壳、部署/状态语言、极简留白 | 偏稀疏，不适合高密度日志 |

## 6. 明确反例（不要什么）

- 不要 LiteLLM 的品牌蓝 + 黑色 CTA 组合，也不要 Ant Design 默认蓝。
- 不要渐变、玻璃拟态、发光边框、3D 插画、装饰性大图。
- 不要彩虹色图表、每根柱子一个颜色、双 Y 轴。
- 不要在控制台里放营销式大 Hero、口号式文案。
- 不要满屏 Beta/New 徽标。
- 不要只做暗色；亮色是默认，暗色可选。
- 不要为了“高级”牺牲可读性：低对比度灰字、10px 正文、过度留白都算失败。
