# L1 页面地图（草案）

> 项目：ai-hub 管理控制台 + 公网演示
> 阶段：P1 · L1（信息架构）
> 状态：**首版范围已确认（2026-11-17：11 个路由页全覆盖，不裁剪）；导航分组待确认**
> 依据：仓库 `feature/phase5-split` 分支上 17 个 Controller 的实际端点（2026-11-16 读取）；`07-LiteLLM UI 操作说明` 的页面与操作流
> 说明：本文只定“有哪些页面、每页放什么、用户来这页完成什么”，**不冻结后端 URL**。接口路径以丘工后续冻结的路径表 / OpenAPI 为准。

## 0. 设计前提

1. **控制台是 console（控制面）的产品。** gateway（数据面）不单独做管理 UI；它的能力通过 Playground / 调试页被“试用”，并在日志、用量、Trace 里被观测。
2. **能力清单从代码反推，不凭印象。** 下表逐个覆盖 17 个 Controller；任何能力都必须有页面入口，不能出现“后端有、前端没入口”。
3. **首版优先服务作品集演示主链**：登录 → 概览 → 建 Key → Playground 试通 → 看日志 / Trace → 看用量；同时保证 8 个能力域都有可进入的页面。
4. **不做 LiteLLM 没有的臆造功能**；也不照抄它不做或做得差的部分（如独立预算页、Agent/Skills/Guardrails）。
5. 每页都必须有 loading / empty / error 三态；列表页筛选条件同步到 URL。

## 3. 每页设计（首版）

> 本节所有页面优先级均为**首版**；后续页面见 §4。每页的“能力来源”只用于追溯，不代表前端可以直接写死该路径。

### A1 登录

- **能力来源**：console 自身（当前后端只有 master key / 虚拟 Key，无控制台会话端点——见 §6）。
- **信息块**：产品名与版本、环境标识（local / demo）、管理员用户名 + 密码、SSO 入口（预留）、安全提示、失败原因。
- **任务路径**：打开 → 输入管理员凭证 → 后端下发会话 cookie → 进入概览；失败可读提示；连续失败触发限流提示。
- **三态**：提交 loading、凭证错误、服务不可达（console 停机时给出明确文案与 gateway 状态）。
- **备注（2026-11-17 已定）**：公网演示直接用管理员账号，不做只读降级或虚拟 Key 混用；会话 = httpOnly + Secure + SameSite=Lax cookie，前端不读、不存 token。前端只维护「已登录 / 未登录」，靠会话探测接口判断；401/403 统一回登录页。

### A2 应用外壳（全局）

- **信息块**：左侧分组导航（可折叠）、顶部面包屑、租户/项目范围切换、环境徽标、账号菜单、全局搜索（后续）、主题切换（后续）。
- **任务路径**：任何页面 1 次点击回到概览；切换租户/项目后当前列表页自动按新范围刷新；随时知道“我在哪个环境、哪个租户”。
- **规则**：租户/项目范围是全局上下文，必须写进 URL 或持久化偏好；不允许各页各自记一套。

### A3 概览

- **能力来源**：Usage（聚合/趋势）、Admin 日志、Trace、MCP runtime、health。
- **信息块**：
  - KPI 卡：今日/近 7 日请求数、成功率、Token、成本、P95 延迟、首 Token 时间（TTFT，若 trace 有）。
  - 趋势图：请求数 / 成本随时间（可切指标）。
  - Top 模型、Top Key、Top 租户。
  - 最近错误：状态码、错误类型、模型、时间，点进日志。
  - 系统健康：gateway / console 状态、MCP 运行时计数。
  - 价格缺口提示：`unpriced_models` 非空时提示“这些模型成本为 0，需补价格表”。
- **任务路径**：登录 → 5 秒判断“系统是否正常、钱花在哪、哪里出错” → 点异常进入日志/用量。
- **三态**：首屏骨架；无数据时给“去建第一把 Key / 发第一个请求”的引导；单块失败不影响其他块。

### B1 虚拟 Key（列表）

- **能力来源**：Admin 列表 / 封禁 / 解封；Key 生成。
- **信息块**：
  - 服务端筛选：租户、项目；状态/模型/关键词只能做页内客户端筛选（当前列表端点不支持，见 §6）。
  - 列（按现有返回字段）：Key 短码、租户、项目、模型白名单、已花费 / 预算上限、状态、过期时间、创建时间。
  - 行操作：封禁/解封、查看（打开组合详情）、复制 Key 短码。
  - 顶部：创建 Key、总数、刷新。
- **任务路径**：找一把 Key（筛选 1–2 步）→ 看花费与状态 → 封禁/解封；或创建新 Key。
- **三态**：空态给“创建第一把 Key”；封禁需二次确认并说明影响；错误可重试。
- **缺口**：管理列表不返回 alias/metadata、RPM/TPM、预算周期，因此列表无法按“用途名称”识别 Key，也不能展示限流字段；已列入 §6。

### B2 创建 Key（抽屉 + 一次性明文弹窗）

- **能力来源**：Key 生成。
- **信息块**：
  - 必填（前端约定，不是后端独立字段）：用途/名称，写入 metadata；模型白名单（留空 = 全部）。
  - 可选：租户、项目、有效期、预算上限、预算周期、RPM、TPM、其他 metadata。
  - 创建结果：一次性明文 Key + 复制按钮 + “只显示一次”警告。
- **任务路径**：填写（默认值合理）→ 创建 → 复制 → 关闭；提供“用这把 Key 去 Playground 测试”的下一步。
- **三态**：提交中禁用重复点击；创建失败保留表单；复制成功反馈。
- **备注**：前端不得把明文 Key 写入 localStorage/URL/日志。

### B3 Key 详情

- **能力来源**：Admin Key 列表字段、Usage（`key_id` 过滤）、日志（`key_id` 过滤）、审计（`target` 过滤）。
- **信息块**：列表可得字段（租户/项目/模型白名单/花费/预算上限/状态/过期/创建时间）、近 7 日花费趋势、最近调用（可跳 Trace）、关联审计、封禁/解封。
- **任务路径**：从列表打开 → 判断这把 Key 是否异常（花费突增、错误多、被滥用）→ 封禁，或去用量/日志下钻。
- **三态**：Key 不存在/已删除的明确空态；趋势无数据时显示“暂无调用”。
- **缺口**：没有“按 key_hash 查单把 Key”的管理端点，详情是由列表字段 + 用量/日志/审计拼合的组合视图；RPM/TPM、预算周期、metadata 在管理列表里没有返回，首版不展示。

### B4 模型与部署（列表）

- **能力来源**：Admin 模型列表/CRUD、gateway 模型别名列表。
- **信息块**：
  - 列（按现有返回字段）：别名、租户、状态、fallbacks、部署数、上游模型摘要。
  - 筛选：租户/状态/关键词为页内客户端筛选（列表端点不接收筛选参数）。
  - 操作：新建别名、编辑、删除、查看详情。
  - 说明条：对外 `/models` 只暴露别名；上游真实模型仅管理端可见。
- **任务路径**：确认“对外有哪些模型可用” → 新增/修改别名 → 配置部署。
- **三态**：无模型时引导“添加第一个模型”；删除需确认并提示影响（正在被 Key 白名单引用）。
- **缺口**：管理 DTO 没有价格、描述与更新时间字段；首版不显示价格列，不做价格维护（见 §6）。

### B5 模型详情 / 部署编辑

- **能力来源**：Admin 单别名查询、部署 upsert。
- **信息块**：别名与租户、状态、描述、fallbacks 编辑、部署列表（deployment_key、api_base、upstream_model、weight、priority、status）、新增/更新部署。
- **任务路径**：进入别名 → 调整 fallback 顺序或部署权重 → 保存 → 返回列表确认状态。
- **三态**：保存失败保留输入；无部署时明确提示“该别名暂不可用”。
- **安全**：部署写入接受 `api_key`，但响应不回显；前端只做“写入/替换密钥”，永不显示、回填或记录明文。描述可写但当前响应不返回，首版只在编辑时提交、不在列表展示。
- **后续**：测试连接、价格与上下文窗口（需要后端补端点）。

### C1 MCP Servers（列表）

- **能力来源**：MCP Server 注册/列表/注销/重探活/运行时统计；工具目录（只读数量）。
- **信息块**：
  - 顶部运行时：活跃 stdio 进程、进行中探活、进行中工具调用。
  - 卡片/表格（可切换）：名称、serverId、transport、endpoint 或 command、租户、状态、最近探活、最近错误、描述。
  - 操作：注册、重新探活、注销、查看详情。
  - 筛选：租户、状态、transport、关键词（页内客户端筛选；列表端点不带筛选参数）。
- **任务路径**：注册一个 Server → 看探活结果 → 打开详情确认工具 → 异常时重探活或注销。
- **三态**：单个 Server 降级不能拖垮整页；错误展示 `lastError` 与重试。

### C2 MCP Server 详情（抽屉）

- **信息块**：连接信息（transport / endpoint / command + args）、健康时间线、最近错误、租户与描述、工具数量与清单入口、运行时计数。
- **任务路径**：从列表打开 → 判断“连不上还是工具没暴露” → 重探活 / 查看工具 / 注销。
- **后续**：工具逐个启用/禁用、鉴权配置。

### C3 工具目录（MCP 页内 Tab）

- **能力来源**：gateway 工具目录/刷新。
- **信息块**：搜索、按 Server/租户筛选、降级 Server 横幅、工具卡（name / originalName / description / inputSchema 展开 / 来源 Server）、刷新按钮。
- **任务路径**：找工具 → 展开 schema → 复制工具名/给 Playground 使用。
- **三态**：无工具空态；部分 Server 降级时仍展示可用工具。
- **后续**：按 inputSchema 生成表单直接调用（走 gateway，需要虚拟 Key）。

### D1 Prompt 模板（列表）

- **能力来源**：模板列表、创建。
- **信息块**：列（名称、最新发布版本、状态、变量、租户、创建人、创建时间）、租户筛选、创建入口。
- **任务路径**：找到模板 → 进入详情 → 新建版本或发布；或创建新模板。
- **三态**：空态引导创建；无发布版本时明确标注。

### D2 Prompt 模板详情 / 版本

- **能力来源**：模板详情、版本历史、发布/回滚、运行时渲染/对话。
- **信息块**：模板内容（只读/编辑）、变量声明与校验、版本时间线、当前发布版本、版本 diff（后续）、渲染预览、试对话（调用 gateway）。
- **任务路径**：编辑内容 → 新建版本 → 预览渲染 → 发布；出问题发布旧版本回滚。
- **三态**：变量不匹配时阻止保存并指出缺失项；发布失败保留草稿；运行时调用失败与保存失败分开提示。
- **备注**：REQ-5.6 会给 get/versions/publish 增加 `tenant_id`，跨租户操作在接口就绪后再做。

### D3 新建模板 / 新版本（抽屉或独立页）

- **信息块**：名称（新建时）、内容、变量列表（从 `{{var}}` 自动提取，可增删校验）、租户、创建人。
- **任务路径**：粘贴内容 → 自动识别变量 → 校验 → 保存 → 进入详情。
- **三态**：变量声明与内容不一致时行内报错，不提交。

### E1 RAG 知识库 · 文档

- **能力来源**：文档上传/列表/重建/删除。
- **信息块**：
  - 项目选择（**必填**）、上传区（拖拽/选择文件）、文档列表。
  - 列：来源文件名、类型、大小、切片数、索引状态、Embedding 模型/维度/耗时/成本、错误信息、重复标记、创建/更新时间。
  - 操作：重建索引、删除（级联切片与向量）。
- **任务路径**：选项目 → 上传 → 看索引状态 → 失败看错误并重建/删除。
- **三态**：上传进度、索引中轮询、失败原因可展开；空态引导上传第一份文档。
- **缺口**：没有项目列表端点，项目选择器的数据来源待定（见 §6）。

### E2 文档详情 / 切片（首版只读元信息；切片浏览待接口）

- **信息块**：文档元信息、索引状态与 Embedding 信息、错误详情、切片总数、删除/重建。
- **任务路径**：从列表进入 → 判断索引是否成功 → 失败时重建或删除。
- **缺口**：当前 17 个 Controller 没有切片列表/分页端点，切片浏览标记为后续，不伪造。

### E3 RAG · 检索调试

- **能力来源**：gateway 检索。
- **信息块**：query、项目、topK、minScore、filters、rerank；结果卡（chunkIndex、source、score、rerankScore、内容片段、chunkId/docId）、noHit 提示。
- **任务路径**：输入问题 → 调参 → 判断召回质量 → 复制 chunkId 回溯文档。
- **三态**：noHit 是正常结果不是错误；调用失败区分参数错误与服务错误。
- **后续**：第五期混合检索上线后展示 `match_type`（vector/keyword/both）与两路分数。

### E4 RAG · 问答调试

- **能力来源**：gateway 问答。
- **信息块**：query、项目、model、topK、minScore、filters、rerank、allowFreeAnswer；答案、引用列表（doc/chunk/source/score）、usage、noHit/freeAnswer 标记。
- **任务路径**：提问 → 看答案与引用 → 点击引用定位来源 → 调参重试。
- **三态**：无命中与“自由回答”必须显式区分，不能把模型自由生成伪装成有依据的回答。

### F1 调用日志

- **能力来源**：Admin 日志查询。
- **信息块**：
  - 筛选：租户、项目、模型、Key、状态码、时间范围。
  - 列：时间、状态、requestId、traceId、Key、租户/项目、模型别名、实际部署模型、prompt/completion/total tokens、成本、延迟、错误类型、callType、targetName。
  - Live Tail / 自动刷新、刷新、重置筛选。
  - 行点击 → 详情抽屉 → 跳 Trace。
- **任务路径**：定位一次失败/慢请求（筛选 + 排序）→ 看详情 → 跳 Trace 追链路。
- **三态**：实时跟随可暂停；空结果给出“放宽时间/筛选”的引导；超大结果分页。
- **备注**：这是信息密度最高的页面之一，L2 样板页备选。

### F2 Trace 详情（日志页抽屉）

- **能力来源**：Trace 按 ID 查询。
- **信息块**：traceId、总段数、总耗时；按 segment 分组的时间线（name、status、latencyMs、payload 展开）、与日志记录互链。
- **任务路径**：从日志进入 → 找最慢/失败段 → 展开 payload 看原因。
- **三态**：trace 不存在（过期/未采样）明确说明；payload 可能很大，默认折叠并提供复制。
- **缺口**：没有 Trace 列表/搜索端点，只能从日志进入。

### G1 用量与成本

- **能力来源**：Usage 聚合/趋势/导出。
- **信息块**：
  - 时间范围与租户/项目/模型/Key 筛选。
  - 总计卡：请求数、prompt/completion/total tokens、成本。
  - 趋势图（按天）；可按指标切换。
  - 明细表：日期 × 租户 × 项目 × 模型 × Key × 请求数 × tokens × 成本。
  - `unpriced_models` 警告与导出 CSV。
- **任务路径**：选范围 → 看总成本与趋势 → 按模型/Key 下钻 → 导出。
- **三态**：无数据空态；成本为 0 时提示价格表缺口；导出失败可重试。

### H1 审计日志

- **能力来源**：审计分页查询。
- **信息块**：筛选（租户、action、target、时间）；列（时间、actor、action、target、traceId）；详情抽屉展示 before/after diff。
- **任务路径**：按人或资源查“谁改了什么” → 看变更前后 → 跳 Trace。
- **三态**：before/after 可能为空，明确显示“无快照”；diff 用并排或增删色，不只靠颜色。

### I1 Playground（对话优先）

- **能力来源**：gateway 的 chat / embeddings / prompt runtime / rag search/answer / MCP call / memory。
- **信息块**：
  - 配置面板：Key 来源（会话内的虚拟 Key / 演示 Key）、Base URL、Endpoint、模型、温度/最大 Token、Tags、自定义 Header、MCP Server、向量库。
  - 对话区：消息列表、流式输出、清空、发送。
  - 指标条：TTFT、总延迟、输入/输出/总 Token、成本、模型。
  - 操作：Test Key、Get Code（curl / Python / JS）。
  - 后续 Tab：Embedding、Prompt 渲染、RAG 检索/问答、MCP 工具、Memory。
- **任务路径**：选模型 → 发一条消息 → 看回复与指标 → 复制调用代码。
- **三态**：流式失败保留已输出内容并标注中断；Key 无效 / 模型无权限分别提示；不把 master key 放进浏览器。
- **备注**：Playground 走 gateway，是“console 停机、gateway 仍可服务”演示的关键页面。

### I2 系统状态

- **信息块**：gateway / console 健康与端口、启动时间/版本（若 health 提供）、MCP 运行时计数、当前环境与部署方式、控制台与数据面是否独立。
- **任务路径**：怀疑故障 → 一屏确认是哪个应用的问题 → 去对应日志/用量。
- **三态**：单个健康检查失败不影响其他块；明确显示检查时间。
- **后续**：数据库/Redis/上游连通性检查（需要后端暴露，不在现有 17 个 Controller 内）。

## 6. 接口缺口与待确认（转丘工 / Q）

> 只列会影响页面能否落地的缺口，不要求现在改；P0/P1 不依赖具体路径。

1. **控制台会话端点缺失（方案已定，端点待补）**：现有鉴权是 master key 与虚拟 Key，浏览器不能持有 master key。已定方案：管理员账号登录，后端下发 httpOnly + Secure + SameSite=Lax 会话 cookie；前端不接触凭证本体。需要后端补：`POST` 登录、`GET` 会话探测、`DELETE` 退出三个端点（具体路径等 5.2/5.3/5.4 收口后冻结）。
2. **项目目录缺失**：RAG 文档接口强制 `project_id`，但仓库没有项目列表端点；Key 生成也需要可选的租户/项目。前端需要项目选择器的数据来源（项目列表，或从 Key/文档聚合）。
3. **文档切片浏览缺失**：现有 17 个 Controller 没有切片列表/分页端点（3.10 提到过分页，但当前分支未暴露）；文档详情首版只做元信息。
4. **项目授权只有 POST**：没有查询端点，无法做可用的授权管理页；已列为后续。
5. **Trace 只有按 ID 查询**：没有列表/搜索；入口只能是调用日志，页面设计按此约束。
6. **Key 查询按明文 Key**：`/key/info` 接收明文 Key，管理台列表应走 Admin Key 列表；Playground 的 Test Key 仍可接受用户输入的一次性明文。
7. **预算/价格不是独立实体**：预算内嵌在 Key，价格不在管理 DTO 中；首版不做独立预算页与价格维护，成本以日志/用量为准。
8. **Prompt 跨租户参数**：REQ-5.6 会给 get/versions/publish 增加 `tenant_id`；在此之前管理页只做默认租户。
9. **健康检查契约**：两应用都有 actuator health，但响应字段（版本、依赖状态）未冻结；系统状态页首版只显示可用的健康结果。
10. **路径口径（主人已定）**：管理面路径**保持 4.4 契约不动**，数据面/控制面靠**凭证物理隔离**，不靠 URL 前缀重排。L1 不写死具体 URL；P2 以冻结的 OpenAPI / 路径表生成客户端。
11. **Key 列表字段与单 Key 查询不足**：管理列表不返回 alias/metadata、RPM/TPM、预算周期；没有“按 key_hash 查单把 Key”的 GET，也没有状态/模型筛选。影响：列表无法按用途识别 Key，Key 详情只能由列表 + 用量/日志拼合。建议后端补 alias/metadata 与单 Key GET；否则前端接受“短码 + 租户/项目”作为识别方式。
12. **模型管理列表字段不足**：返回只有 alias、tenant、status、fallbacks、deployments；没有 description、价格、更新时间，也不接收筛选参数。首版不显示价格与描述，列表按小数据量做页内筛选。
13. **部署密钥写入**：部署 upsert 接受 `api_key`，响应不回显。前端必须按“只写不读”处理，严禁把明文写入日志、URL 或持久化存储。

## 7. L2 样板页与下一步

- **样板页**：MCP Servers 列表 + 详情抽屉。理由：同时覆盖卡片/表格、状态徽标、筛选、注册表单、抽屉详情、空态/加载/错误，信息密度足够，且不依赖复杂图表。
- **L2 交付**：同一页面 2–3 个视觉方向，全部上 Design Board，并排看 1440/1280/768 三档。
- **L3 顺序**：布局密度 → 色板 → 字体层级 → 组件细节 → 交互反馈；每轮只动一个维度。
- **L4**：其余页面套用 `DESIGN-BASELINE.md`，只确认信息架构与特殊交互。
